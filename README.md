# 卷材厚度 P95 核算台

针对「部分卷只留了测厚摘要」的场景：质检员按批号、卷号登记每卷的
**测点数、最薄值、P95、最厚值**（整数微米），也可以为单卷上传完整读数
CSV。系统据此计算整批 P95 的可行区间，并给出 **必超限 / 必不超限 / 待补明细**
三种判定。复卷台把两卷余料接成一卷时，还可在成品批次页用实际接上的测点
为成品卷建档。

## 运行

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据保存在命名卷 `qc-data` 的 `/data/qc.db` 中。本地直接运行：

```bash
pip install -r requirements.txt
QC_DB=./data/qc.db python app.py   # http://localhost:8000
```

## 规则

* P95 定义为升序第 `ceil(点数 × 0.95)` 个读数，用整数运算
  `(95n + 99) // 100` 计算位次，避免浮点误差。
* 摘要必须能同时成立才允许登记，例如 2 点卷的 P95 必然等于最厚值。
* 单卷明细 CSV 的读数个数、最薄值、P95、最厚值必须与已提交摘要全部相符，
  才启用为核算依据；否则存档并停用，核算退回摘要。
* 换交摘要时，旧摘要作废；原明细若与新摘要不符则停用，改按新摘要核算。
* 一次判定读取并在同一事务内固化当时的有效摘要/明细快照；判定结果连同
  快照一起落库。后续改档不会改写历史判定。
* 写入失败整体回滚，原档案与历史判定保持不变。
* 摘要从不展开为逐点读数：整批区间通过对每卷的闭式计数做阈值二分求得。

## 复卷接带成品建档

* 在成品批次页填写新成品卷号，从**其他批次**选两卷当前有效的上传明细
  （须为两个不同的原卷），按接带顺序填写每段测点的起止序号。
* 序号按所选明细 CSV 的原顺序从 1 起算，首尾都计入；每段必须完全落在该
  原明细的测点范围内，起止不能倒置。
* 同一份原明细里的每个测点最多用于一卷成品：已被占用的区间再次提交会被
  拒绝；互不重叠的相邻区间可以分别建档。
* 成品摘要（测点数、最薄值、P95、最厚值）由两段读数按接带顺序拼接后实算，
  并写入该成品卷的有效摘要档，供原有的整批判定直接使用。成品档案页按接带
  顺序列出每段的原批次、原卷号、原明细号与起止区间。
* **读数只存一份**：成品卷只引用原明细的行号区间，不复制读数 JSON。
* **源卷换档后成品不变**：建档时把原明细号与区间冻结在接带段中；源卷之后
  换交摘要、停用明细，成品仍按建档时的原件区间核算。
* 算成品批次统计时，其他批次的档案与判定照常交档、互不影响。
* 提交在单个事务内完成：任一原明细已换下或停用、任一区间已被占用、成品
  卷号已存在或保存出错时，成品档与本次占用都不生效，原档案保持不变。

## 整批区间的原理

设整批 N 个读数、P95 位次为 `k = ceil(0.95N)`。

* 整批 P95 ≤ t，当且仅当可以有至少 k 个读数 ≤ t；
* 整批 P95 ≥ t，当且仅当可以有至少 `N-k+1` 个读数 ≥ t。

对每个只留摘要的卷，能在不展开读数的前提下，用 `(n, min, p95, max)`
直接算出「≤ t 的读数最多几个」和「≥ t 的读数最多几个」（`qc.py`）。
各卷相互独立，因此求和后对 t 做二分即可得到精确的最小/最大值。

## 目录

* `app.py` — Flask 路由、SQLite 存档、CSV 解析、复卷接带建档与占用
* `qc.py` — P95 位次、摘要可行性、闭式计数、整批区间
* `templates/` — 页面（含 `finished.html` 成品档案页）
* `tests/` — 数学穷举校验、Flask 流程测试与复卷成品建档测试
